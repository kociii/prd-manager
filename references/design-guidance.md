# 界面设计指导

设计默认输出 design.md，以 ASCII 线框图表达结构，文字和表格补充视觉、行为与约束。先做设计判断，再画图；字符图不是把所有需求方框化。

## 1. 读上下文，确定页面任务

读取相关 PRD、现有页面、品牌规范和组件库。区分产品已有规则、用户明确偏好和本次建议；未经确认的品牌重设计不能混入功能迭代。

每个页面先回答：谁在什么场景使用？第一眼应看到什么？最重要的动作是什么？完成后去哪？哪些信息支撑决策？哪些失败/权限/极端数据会改变布局？

在页面规格中简述“目标 → 关键决策 → 设计理由”。例如：客服需要连续核对订单，因此选择列表+详情分栏以保留上下文；不能只写“现代简约、提升体验”。

页面编号稳定。推荐使用 `## D01-orders` 作为标题，下一行注明中文页面名，让 `design.md#d01-orders` 成为稳定引用。修改时不因重新排序而重编号。

## 2. 选择合适的信息架构

| 使用场景 | 通常合适的布局 | 需要判断的取舍 |
|----------|----------------|----------------|
| 大量记录查找与比较 | 筛选/结果表格/分页 | 表格适合字段对齐比较；移动端可转摘要列表，保留关键字段和动作 |
| 连续处理多个对象 | 主从分栏（列表+详情） | 保留列表上下文；窄屏改为列表到详情并定义返回位置 |
| 一次复杂编辑 | 分组表单或步骤流程 | 简短表单不拆成向导；跨步骤保留输入与校验结果 |
| 高频状态监控 | 关键指标+趋势/告警+可行动列表 | 指标必须支持判断或操作，不为填满页面堆卡片和图表 |
| 阅读与确认 | 详情/摘要+主操作 | 先显示决定行动的信息，再放辅助说明；长内容考虑锚点导航 |
| 临时的小范围任务 | 弹窗、抽屉或内联编辑 | 弹窗适合短任务/确认；需要持续参考背景可用抽屉；复杂长任务用独立页 |

同级切换用 tabs，步骤顺序用 stepper，全局去向用导航；它们解决不同问题。侧栏、页头、面包屑不要同时重复同一层级。

## 3. 信息层级与视觉规范

- 明确页面标题、区块标题、主信息、辅助信息和状态的阅读顺序。首屏容纳任务入口与决策信息，不让装饰抢占重点。
- 在同一任务区域确定明确的主行动，并按上下文配置次行动；破坏性动作与主提交区分，不通过颜色单独表达风险。
- 用分组、间距和对齐表达关系。不要给每个文本都套卡片；密集后台与内容消费页面采用不同密度。
- 统一同类页面的导航、筛选区、表单标签、表格操作、空状态和反馈位置。优先复用项目组件，组件名表达语义，框架实现放 dev.md。
- 视觉信息无法从 ASCII 推导，应单独写明确的 token/规格：字体层级、字重、行高、色彩角色、间距、圆角、边框、容器宽度与表单控件尺寸。引用现有规则；无现有系统时给一组少量且一致的建议并标明“本次建议”。

**视觉规格记录格式**：`角色/元素 → 值或项目 token → 适用范围 → 来源/理由`。不要只写“适当留白”“按钮醒目”。不要把 ASCII 的一列字符当作固定像素比例。

## 4. 组件与内容决策

- 表单标签持久可见；placeholder 提供示例，不代替标签。必填、格式、校验触发时机和错误恢复要明确。
- 少量互斥且需比较的选项可用单选；大量选项可用选择器/搜索选择；多选和立即生效的开关区别对待，说明保存时机。
- 表格对齐按数据类型确定；数值便于比较，操作列位置稳定。排序、分页、筛选联动与保留规则要写出，不只画一个搜索框。
- 使用具体、符合业务的数据和文案（演示值标为示例）。涵盖长名称、多位数金额、日期、缺失值和超过一屏的数据；不能用 lorem ipsum 或“内容区域”替代正式信息结构。
- 隐藏、禁用、只读是不同状态：说明适用原因、用户可否得知原因以及下一步途径。权限变化以业务规则为准，不擅自扩大权限。

## 5. 交互与状态闭环

为重要交互记录 `元素 ID → 触发 → 前置条件 → 界面变化/反馈 → 去向/恢复 → 验收关联`。主按钮有去向，返回有落点，关闭有状态处理。

按风险选择状态，不为每页机械补全矩阵：

| 状态 | 需要设计的细节 |
|------|----------------|
| 加载/提交中 | 原内容是否保留、反馈位置、能否取消或重复点击 |
| 空数据 / 无搜索结果 | 区分首次无数据与筛选无结果，给创建入口或清除筛选 |
| 失败/超时/断网 | 错误可理解、保留输入/上下文、重试动作与返回路径 |
| 校验不通过 | 字段附近说明原因，定位首个错误，纠正后如何清除提示 |
| 成功 | 反馈出现在哪里、下一步去向、是否关闭或清空表单 |
| 无权限/只读 | 能看到什么、不能做什么、解释和合法下一步 |
| 高影响操作 | 确认对象与后果、处理中行为、失败恢复；遵循业务确认规则 |

结构变化大的状态补图：例如空列表替代结果区、弹窗、移动端重排；仅提示文案变化可用元素/状态表表达。ASCII 中未展示的复杂行为也须写清，不把“点击后提交”当作完整规格。

## 6. 响应式与可访问性

- 根据真实目标设备、容器和内容决定断点；不要默认所有移动端都改底部导航。
- 逐个重要区域说明保留、换行、堆叠、折叠、移入抽屉或横向滚动。主操作不能因变窄消失；长表格的首选字段与详情入口明确。
- 如果桌面与移动端结构不同，为同一页面增加独立视口线框并写保留规则；只有边距变化无需复制整图。
- 区分页面滚动、局部容器滚动、吸顶页头和固定底部操作。固定区不得遮挡内容，长表单考虑软键盘。
- 定义阅读/Tab 顺序、可见焦点、文本标签、状态播报、弹窗打开时焦点进入及关闭时返回、Esc/取消语义。不要靠 hover 或颜色单独传递关键动作/状态。
- 标准目标优先沿用项目要求。未约定时可建议 WCAG 2.2 AA：普通文本对比度至少 4.5:1，大字及必要 UI 边界通常至少 3:1；实际颜色实现后测量。移动端主触控目标可建议不小于 44×44 CSS px，并说明这是易用性建议，非从 ASCII 测得。

## 7. 页面/组件层级：指导开发拆分

每个有 UI 的页面在 ASCII 后**必须**输出布局层级树，不能只交付视觉线框。层级表达页面内的包含和职责关系；页面间的跳转另用流转表，代码文件树由 dev.md 决定，三者不能互相代替。

推荐层次：`页面 Pxx → 布局/区域 Rxx → 业务组件 → 基础控件 Cxx`。design.md 的必填章节名为“布局层级关系（必填）”。层数按实际职责决定，不为凑树深拆出大量无职责包装。使用框架无关的语义名，保留稳定 ID 与中文说明。

- 每个有独立任务、独立状态或复用价值的区域/组件成为一个节点。只有样式间距用途的包装层可省略，避免一行文字一个组件。
- **包含关系**：树只写谁包含谁。Grid/Flex 的方向、比例、固定/滚动和响应式重排在布局表说明。
- **重复关系**：列表项标 `[repeat: order.id]` 等稳定键；共享一个组件定义 ID，以业务键区分实例，不为每行复制一套组件规格。
- **条件关系**：加载/空/失败、权限区块和弹窗标条件分支；注明替换哪个区域或作为覆盖层呈现。组件树只引用适用状态，不凭空扩展功能。
- **复用边界**：标已有公共组件/本版复用/页面私有；页面框架与业务组件区分，不能因长得像就把业务不同的组件合并。
- **状态与事件**：树下用“开发拆分说明”表格说明每个关键节点的渲染职责、输入、拥有的状态、向上发出的用户事件及父级处理。业务数据来源/契约只写语义，接口字段和状态管理库放 dev.md。

示例：筛选组件拥有尚未提交的输入草稿，提交筛选条件给页面；页面拥有生效的筛选、页码和结果状态；结果区展示页面给的数据并发出“查看某订单”；分页组件发出“请求页码”，不自己再维护另一套生效筛选。

简单页面可以是一个小树加短表，不必过度组件化。开发者应能据此回答：从哪层拆分、谁负责状态、子组件能做什么、交互由谁处理。

## 8. 多页面版本组织与交付

使用 `assets/design_template.md`：先概述本版设计方向和页面清单，再按页面组织正常态/变化态、组件层级、元素、交互、适配与验收关系。公共组件和视觉规则集中维护，页面只写差异。

每页分配 Dxx，关键区域用 Rxx，交互元素在页内用 Cxx，状态用清晰名称；跨页引用写完整 ID（如 D01-orders/C03）。对应关系为 `需求 Sx → 页面 Pxx → 元素/状态 → 验收用例`。

局部修改只更新受影响页面、状态和公共规则，不重画无关页面。旧稿读懂后增量改进，保留稳定 ID 和历史设计决策。纯后端无 UI 不生成空 design.md。

交付前做两层检查：

1. **表达检查**：图边框对齐、符号一致、图中的区域/控件 ID 与层级树和表格对应、页面跳转和需求链接存在。
2. **设计检查**：能完成主任务，信息优先级合理，主要状态可恢复，响应式/键盘/长内容已考虑，视觉规格足够实现。

设计阶段不声称已完成浏览器或真实产品验收；实施后对照页面/状态规格验证。ASCII 对齐通过不代表设计质量通过。

## 参考理念

本轮官方资料调研（2026-09-21）借鉴的是设计组织和交付方法，不依赖这些平台或改用它们的输出格式：

- [Figma](https://www.figma.com/design/)：共享组件、变量、自动布局和跨页面一致性。
- [Penpot 原型](https://penpot.app/design/prototyping)：页面流转、覆盖层、滚动和反馈共同构成完整体验。
- [Paper](https://paper.design) 与 [v0 的 Paper 交付说明](https://v0.app/docs/paper)：页面、状态和定位清晰命名，交付时说明屏幕之间的关系。

将这些原则落实到 ASCII + 文字规格；不把平台能力或营销宣传当作本 skill 已实现的功能。
