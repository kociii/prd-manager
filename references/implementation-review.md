# 实现审查与修复闭环

用于开发完成后的版本审查、PRD↔代码审计，以及用户要求检查 AI 生成代码的场景。目标是让使用人根据功能、效率和验证证据判断结果，无需逐行读代码。单纯创建 PRD、列版本或改文案时不启动完整审查。

## 范围与基线

先读取相关 PRD、dev.md、实际变更和项目检查命令；UI 功能对照 design.md 的页面 ID、视口、状态与流转。记录需求版本、提交号或工作区状态、检查范围；未提交变更以 diff 或文件快照标识。没有代码时只能评审方案，不能声称实现通过。

- 已确认的需求决定预期行为；实际代码提供实现事实；二者冲突时记录偏差，不能改文档来掩盖缺陷。
- 继承项目已有架构约束、检查规则和性能目标。缺少性能目标时说明测量口径及假设，不臆造达标阈值。
- 小补丁在任务中记录三项结论即可；跨模块、新架构或正式版本审查使用 `assets/review_template.md` 生成版本目录下的 `review.md`。
- 用户只要求审查时输出报告；用户已授权实现或修复时，继续修复范围内的问题。审查本身不代表提交、合并、部署或变更需求的授权。

## 第一轮：从代码解释实现，核对需求与架构

这一轮先理解和核对，不顺手重构。

1. 沿真实入口、调用链、状态变化和数据读写，解释功能如何运行。复杂链路可配 Mermaid 图。
2. 列出核心模块职责、关键算法及选择理由、接口输入/输出/错误契约、数据流、外部依赖和副作用；标明代码路径和符号。无法从代码确认的设计理由写「待确认」，不要替实现者编造动机。
3. 建立 `需求 ID → 设计约束 → 代码路径/符号 → 测试 ID/证据 → 结论` 映射。检查遗漏、越界功能、算法偏移及接口兼容性。
4. 区分「有文件」「有实现」「行为已验证」。文件名、注释、测试名或 AI 总结都不能单独证明需求已满足。
5. 输出已实现/部分实现/缺失/未验证及偏差。说明基础设施、重构和既有功能的来源，不把每个辅助函数都判成无需求依据。

## 第二轮：检查逻辑、低效算法和冗余调用

基于实际代码独立检查第一轮结论。优先追踪反例，而非重复实现者的解释。

| 维度 | 重点检查 | 可用证据 |
|------|----------|----------|
| 正确性 | 分支遗漏、状态流转、权限、精度、事务、并发和幂等 | 触发输入、调用路径、可复现失败 |
| 算法与资源 | 输入规模增长后的时间/空间复杂度、无界循环或重试、资源释放 | 复杂度推导、数据规模、调用次数 |
| 调用与数据 | N+1、重复请求/计算/渲染、过量读取、无效缓存 | 查询计划、调用追踪、计数、剖析数据 |

每条发现带问题 ID、严重度、代码位置、触发条件、影响、证据、最小修复建议和复测方式。区分「已确认」与「待验证」；不能把推测写成已测结果。

优化应对应实际成本或瓶颈。声称“变快”需记录同环境、同负载下的基线和改后指标；仅做静态推导时只能声称复杂度或调用次数变化。检查项目已有格式、lint 和类型约束，但不因个人审美重写代码。命名混淆、重复逻辑或强耦合会造成具体缺陷时，说明风险后处理。

若运行环境允许多 Agent，可按功能一致性、逻辑与数据、性能分别做只读审查，主 Agent 去重并核实；不能默认具备该能力或强制拉起一堆 Agent。无此能力时分轮串行，不能声称做过独立 Agent 审查。修复共享文件时明确负责人或串行处理。

## 第三轮：按风险验证边界，修复并回归

测试预期来源于需求和业务不变量，不照抄当前实现。按 `references/test-driven.md` 建立适用的边界矩阵；优先覆盖高影响路径、跨模块接口和实际发现的问题，不以用例数量或行覆盖率替代有效性。

闭环：`复现/反例 → 定位原因 → 最小修复 → 原用例复测 → 受影响链路回归 → 更新证据`。

- 修复改变契约、算法或数据流时，回到第一轮更新实现摘要和需求映射；影响性能时补对应第二轮检查。
- 不删除失败用例、放宽断言或修改预期来制造全绿；测试自身有错时以需求为依据记录修正理由。
- 记录真实命令、环境、数据规模、执行结果和日志位置。未运行、失败、环境阻塞、人工待验收分别标记。
- 必要检查通过且没有新变更或新证据时停止重复测试。相同失败连续两轮修复仍未解决时，暂停同一路径盲修，记录已尝试方案并重新定位；依赖用户信息或外部环境时明确未完成项。

## 交付给使用人的三项结论

1. **功能与架构**：哪些需求已验证、哪些偏差或遗漏未解决。
2. **逻辑与效率**：修复了什么、性能证据是什么、还有哪些未测瓶颈。
3. **测试与边界**：哪些关键路径和适用边界已验证、哪些失败或待验收。

每项附最短证据入口和剩余风险。AI 自测通过与使用人验收通过分开记录；没有实际运行不能标为测试通过，存在影响验收的未解决问题不能标为版本完成。
