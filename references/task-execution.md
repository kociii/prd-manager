# 任务拆解与执行

## 拆解

读取 PRD、dev.md 和 test.md 的相关章节；UI 任务读取 design.md 的对应页面的 ASCII、组件层级、职责/状态归属及交互规格，以独立可交付功能拆任务。使用 `assets/task_template.md`，放入版本的 tasks/ 目录，并生成含依赖关系的 README.md。任务大小按可验证性和依赖划分，工时仅作估计。

每个任务关联需求 ID，给出输入、输出、文件职责、接口契约、关键不变量和验证方式。UI 任务同时关联页面/组件 ID，按有独立职责的子树拆任务，不把每个框都拆成任务。复杂设计链接 dev.md，不复制完整实现代码。仅请求规划时到此交付。

## 执行

1. 检查相关需求、设计及前置依赖。已有授权和已确认决策继续沿用；缺失信息影响正确性时才澄清。依赖阻塞时先推进独立工作。
2. 实现任务并更新状态，不因创建了文件就勾选验收通过。
3. 按 `references/implementation-review.md` 完成三轮检查：从代码解释并核对实现；查逻辑、复杂度和冗余调用；测试边界、修复、回归。小任务在任务文件简记，复杂任务链接 review.md。
4. 读取项目实际测试、lint、类型检查或构建命令，执行与变更相称的必要检查。修复缺陷优先保存能揭示原缺陷的回归用例，不为纯文案调整堆测试。
5. 记录代码位置、命令、结果和剩余问题。必要检查未执行或仍失败时，状态为待验证/阻塞，不能写已完成。
6. 更新受影响的 dev.md、test.md、CHANGELOG 和任务索引；AI 自测完成与使用人验收分开记录。提交、合并和部署按用户授权及项目规则执行，不自动纳入每个任务。

## 并行协作（按能力和范围选用）

只有无依赖且边界明确的任务才并行。为执行者分配文件/模块职责，说明其他人也在修改，不覆盖他人变更；需要分支隔离时使用独立 worktree 或 checkout，不能在同一个工作区并发切分支。

审查者优先只读，主执行者去重、复核并安排修复。共享文件修改串行整合，整合后验证受影响链路。没有多 Agent 工具时按同样顺序串行完成，不假装独立审查。

## 完成判据

- 范围内需求和契约有实际实现，偏差已解释或解决。
- 影响验收的逻辑问题已修复；性能结论有测量或明确的静态推导依据。
- 关键路径与适用边界有验证证据，项目既定检查满足；覆盖率只作辅助指标。
- 任务与版本状态准确：规划中、进行中、待验证、已完成、阻塞、已取消；待用户验收另记。

修复按「复现 → 定位 → 修复 → 原场景复测 → 受影响回归」推进。相同失败两轮无进展时重新诊断，不能靠放宽断言或重复同一命令闭环。需要外部信息时记录具体缺口，继续不依赖该缺口的工作。
