# <version> 测试与验收文档

> 本文档回答「**如何验证这个版本做对了**」，服务两类人：
> - **AI / 开发者**：第 2 章开发自测清单——描述要测什么，不写测试代码本身。
> - **使用人**：第 3 章验收用例 + 第 5 章验收记录——照着操作、逐条打勾。
>
> 功能需求 → `prd.md`　　技术实现 → `dev.md`　　部署运维 → `ops.md`

## 2. 开发自测

> 按项目类型选择本节内容：后端项目以单元测试清单为主；前端项目必含界面测试；全栈项目两者都含。
> 本节描述「要测什么场景、什么输入、什么预期」，具体测试代码由开发时编写，不堆在文档里。

### 2.1 单元测试清单（后端项目为主体）

> 覆盖每个功能点的正常、边界、异常三类场景。

| 模块 | 测试场景 | 输入 | 预期结果 |
|------|---------|------|---------|
| [模块名] | 正常：[场景描述] | [输入] | [预期] |
| [模块名] | 边界：[如金额为 0 / 列表为空] | [输入] | [预期] |
| [模块名] | 异常：[如参数缺失 / 余额不足] | [输入] | [预期错误提示] |

**验证目标**：覆盖关键业务不变量及适用边界；覆盖率阈值沿用项目约定并注明统计范围，不能代替行为正确性证明。
